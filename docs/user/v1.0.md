# Atropos 1.0: supported reference configuration

Atropos 1.0 is the independently installed rule/workflow engine and API client.
Its stable support claim is bounded to the reference below. The runtime works
without Atraxis and without an AI provider. Trusted registered actions, explicit
dispatch and current authorization remain required.

| Component | Qualified reference | Boundary |
| --- | --- | --- |
| Packages | `atraxis-atropos` 1.0.0 and `atropos-client` 1.0.0; Linux amd64; Python 3.11/3.12 | Independent engine, client and service installations |
| Operational storage | SQLite and integrated queue; Python 3.12 | Single-host operation; coordinated cold recovery onto a distinct host |
| Rules/workflows | Existing version-1 YAML rules and bounded version-1 workflow graph; ZEN 2.1.2 | Typed finite inputs, explicit bindings and registered actions; no arbitrary JDM, scripts or implicit activation |
| Service authority | Existing versioned profile and verified TLS; delegated actor/organization and trusted inventory | Current scoped permissions checked at admission, execution and reconciliation |
| Execution | Auton 1.3.1 source `7f57348b144fa62400bad31160d4b4ad5c00f53c` with the bounded transport patch described in Atraxis's Compose guide | One approved non-destructive HTTPS diagnostic; arbitrary remediation and unattended policies require separate qualification |
| Notification | Alertmanager adapter and existing local webhook receiver | Actual firing/resolution receipt verified locally; external email/Slack/provider delivery is separate |
| Other backends | Existing Redis, PostgreSQL and MySQL/MariaDB implementations | Contract, constraint, recovery and TLS tests retained; no additional operational capacity/recovery promise |

The functional engine/client modules match the operationally qualified source;
only their package/runtime version constants change. The reference includes
coordinated recovery of accounts, audit, configuration, queued work and uncertain
locks; verified renewed TLS; current authority checks; and paused execution after
restore. The actual approved diagnostic completed once, its local notification
was received, and a fresh duplicate was refused without replaying the action.

The retained four-hour synthetic SQLite/Redis campaign keeps its original inputs:
14,436.558 seconds of load, 292 cycles, 7,300 test admissions, then 653.346 seconds
of quiescence. It is not a live capacity or integrated-queue endurance benchmark,
an SLO, or evidence of indefinite leak-free operation.

## Install and match components

Use separate environments for the engine service and its consumers. Download both
attached wheels from the GitHub release. With the system libmagic library present:

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install './atropos_client-1.0.0-py3-none-any.whl[observations]' './atraxis_atropos-1.0.0-py3-none-any.whl[service]'
python -m pip check
atropos --help
```

This installs the service dependencies without starting a service or granting an
action. A consumer that only needs the base client installs its wheel alone;
the client has no engine, Redis or ZEN dependency. The engine's base wheel alone
provides the trusted local workflow CLI. See [service setup](rule-service.md),
[backend selection](backends.md) and [approved executors](execution-adapters.md).

Atraxis 1.0.0 retains its separately pinned 0.1.0a10 consumer client. Its functional
client code is identical to 1.0.0, apart from the version constant; the wire and
profile contracts are unchanged. Do not force incompatible package pins into one
environment or silently upgrade deployed components. This release does not publish
to PyPI or replace an existing service by itself.

## Recovery and format boundary

Back up state and configuration before changing an installation. Preserve current
revocations and surviving external-effect evidence; never overwrite them with a
stale authority snapshot. An unknown action remains uncertain until an authorized
operator reconciles it. A queue receipt or signed admission never grants execution.
No automatic resume or blind retry is introduced.

Supported configuration, API and storage formats are explicitly versioned.
Unsupported prototype formats are rejected without conversion or deletion.
Prototype compatibility and arbitrary component combinations are not promised.
High availability, hot backup, automatic purge, cross-backend conversion, new
languages and sandboxing arbitrary registered code remain outside this release.
