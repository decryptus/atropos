# Atropos 1.0.1

This patch changes rule visibility and Auton execution refusal. It preserves the
wire format, storage schema and Basic credential configuration of 1.0.0.

- A missing rule and an inaccessible revision produce the same HTTP 404 on
  lookup. Activation checks the relevant scopes before reporting a generation
  conflict. A creator may still learn that an organization-wide name is taken.
- An unexpected internal key error produces HTTP 503 with an unknown outcome.
- An Auton target mismatch, an invalid execution context, unavailable local
  credentials or CA, or a changed approved adapter cancels the workflow before
  submission. The worker skips the error branch on these refusals.

The engine and independent client are built together. Existing installations can
continue using 1.0.0 while the candidate is qualified.

## Qualification status

The 1.0.0 operational record covers its original Linux amd64, SQLite and
integrated-queue reference. The HTTP authorization and pre-dispatch behavior
changed in this patch. Candidate package checks and the isolated Auton integration
exercise the new sources. The operational diagnostic and correlated receiver
result must be reviewed for this candidate before stable promotion. The existing
cold-recovery and endurance results keep their original inputs and limits.
