# Atropos 1.0.2

The Auton executor can now authenticate each job with a scoped Bearer token. The engine and independent Atropos client use version 1.0.2. Existing Basic profiles continue to work with a Basic-authenticated Auton daemon.

## Migrate an action

1. Configure the target Auton daemon for SQLite authentication. Issue a token with a bounded lifetime and the read and run scopes for an account authorized on the endpoint. Use HTTPS for a remote daemon.
2. Store the token in a private file owned by the Atropos worker with mode 0600. In its execution adapter profile, replace both `username` and `password_file` with `token_file`. Relative paths resolve from the profile directory.
3. Run `atropos execution-adapters --config /path/to/engine.yml`, review the new adapter revision, and approve the updated binding. Restart the worker to load the changed adapter definition. Run one approved diagnostic.
4. For subsequent rotation, issue the replacement, replace the token file atomically at the same path, verify a job, then revoke the previous token. The worker reads the file at dispatch. The existing binding and running worker pick up the replacement.

The [executor guide](../user/execution-adapters.md) includes a complete profile. Storage and workflow schemas require no migration.
