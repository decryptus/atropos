# Atropos 1.0.0

First stable engine and independent client for the documented Linux amd64,
Python 3.11/3.12 reference configuration. It includes versioned YAML rules,
ZEN 2.1.2 decisions, explicit lifecycle operations, authorized bounded workflows,
durable deduplication, target exclusion, uncertainty reconciliation and a separate
authenticated service/client boundary.

The operational reference uses SQLite with the integrated queue, verified TLS,
current scoped authority and explicitly approved registered actions. Qualification
includes coordinated cold restoration on a distinct host, retained state/audit and
execution pause, one actual non-destructive HTTPS diagnostic through Auton,
local Alertmanager firing/resolution receipt and duplicate refusal. Historical
four-hour SQLite/Redis evidence retains its original synthetic scope. Existing
SQL/Redis backends retain their separate contract/TLS evidence.

Engine and client functional Python modules are unchanged from the qualified
reference; package/runtime version constants now report 1.0.0. External mail/chat
recipients, arbitrary remediation, production throughput, high availability and
hot backup are outside this support claim.

The four attached archives are the exact successful Python 3.12 installed-package
CI artifacts; Python 3.11 also passes. `release-provenance.json` records source,
checks, bounded qualification and archive hashes. `SHA256SUMS` covers attachments.
No PyPI publication or automatic service replacement occurs.

Follow the [1.0 support and installation guide](https://github.com/decryptus/atropos/blob/v1.0.0/docs/user/v1.0.md).
Install the matched engine/client wheels in a dedicated service environment.
Atraxis 1.0.0 keeps its existing independently pinned consumer client; the wire
contracts are unchanged. Back up state before an explicit upgrade; unsupported
formats fail without conversion/deletion.
